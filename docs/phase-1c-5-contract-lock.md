This is a documentation-only decision. No UI, API, test, annotation, generated contract, migration, dependency, infrastructure or CI change is authorized. V1–V12 remain byte-for-byte unchanged; no V13. An A gap identifies work needing separate authorization, not permission to fix it here. ## 3. Authorization

AUTH checks the authenticated Actor's **issuer + subject** against an ACTIVE `platform_role_assignment` with `role='PLATFORM_ADMIN'`. `GET /api/identity/capabilities` returns `IdentityCapabilities.platformAdmin` from this same live service. There is no inferred authority from organization membership, ORG_OWNER, ORG_ADMIN, organization type, Supplier/Facility relationships, selected Organization or route knowledge. There is no frontend actor field that grants authority.

| Capability result                | Locked UX                                                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pending                          | Accessible loading state; no protected form, query or command mounts                                                                              |
| Successful `false`               | Safe access-denied state for direct admin URLs; no admin data fetch                                                                               |
| Successful `true`                | Protected routes/controls may mount                                                                                                               |
| Request error / malformed result | Access-check error with safe reference and explicit retry; never substitute true or false                                                         |
| 401 / Actor change / logout      | Existing session boundary cancels/clears queries and remounts drafts; discard pending command keys and evidence selections owned by the old Actor |
| Command 403 / revocation         | Stop commands, recheck capabilities, remove protected controls and admin cache; do not reinterpret as validation failure                          |

Server enforcement is separate: all inspected canonical/reference/Source command service entry points call `auth.requireAdmin()`, as do protected Source/evidence reads. Security requires authentication for non-public API paths. Validation/controller binding can reject malformed input before service authorization, so a malformed buyer request can be 400; a valid unauthorized command is 403. Frontend hiding never substitutes for server checks. CORS already permits POST/PUT/PATCH and `Idempotency-Key` for configured exact origins; no CORS change is needed.

Reuse the accepted memory-only credentials, opaque session scope, safe API client, fail-closed capability states and `mutations.retry=false`. No persistent admin cache or draft in localStorage/sessionStorage. Production admin provisioning remains the explicit operator procedure in [bootstrap documentation](platform-admin-bootstrap.md), with no public bootstrap endpoint or production automatic seed.

### Exact decimal strategy (future shared helper decision, no implementation here)

Keep text drafts, validate ordinary decimal lexical form, sign, integer/fraction digit envelope and exact range per field. Never Number/parseFloat/parseInt for decimal quantities, floating arithmetic, `toFixed`, scientific notation conversion or silent rounding. Exact comparisons and composition sums use scaled **BigInt** with explicit scale, returning strings; do not route through a JS numeric intermediate. Canonicalizing only insignificant zeros is permitted, but reject excess declared scale instead of silently removing significant digits to fit. HTTP serializers send generated string properties. Server BigDecimal/NUMERIC validation remains authoritative. Extend the existing exact-decimal helper for signed/six-decimal coordinates; its current nonnegative four-decimal search helper is not sufficient for every admin field.

## 17. Error / recovery matrix

ERR produces ProblemDetail with `type=urn:source-os:problem:<status>`, status/title/detail and requestId; security 401/403 use the same fixed safe shape. RequestIds are bounded safe correlation values. OpenAPI currently lacks a comprehensive typed ProblemDetail response schema. The existing ApiError adapter uses status/fixed messages and safe request/reference ID, not raw body/detail/stack/authentication data.

| Result                                 | Actual causes / distinctions                                                                                                                                                                                                         | Locked recovery                                                                                                                                                                                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400                                    | Bean binding/validation, unsupported enum/manual verification target, identity reassignment service guard, wrong Variant parent, wrong binding Record kind, invalid hash pair/decimal/currency/interval/mode                         | Keep draft; show safe field validation when locally known, otherwise generic invalid input + reference. Never parse exception text into an invented field/code.                                                                                            |
| 401                                    | Missing/expired authentication                                                                                                                                                                                                       | Existing session expiration/cancellation/remount. No replay under another Actor, no persisted credentials/drafts.                                                                                                                                          |
| 403                                    | Authenticated Actor is not active PLATFORM_ADMIN; live grant revoked                                                                                                                                                                 | Fail closed, stop writes/admin queries, refresh capability; organization ownership does not override it.                                                                                                                                                   |
| 404                                    | Service `missing()` for primary or pre-read references                                                                                                                                                                               | Keep unsent draft only in current Actor scope, explain missing context; offer supported existing browse/refresh. Do not say every missing FK must be404: many are409.                                                                                      |
| 409                                    | Version CAS/ORM conflict, no-op verification target, duplicate natural key, binding target conflict, Observation/Price/Inventory idempotency conflict, FK/CHECK/trigger integrity failure; Source/most reference missing-update rows | Generic conflict banner + safe reference, explicit refresh/read comparison, retain draft. No silent overwrite, new-version auto-retry, provider workaround or automatic new identity/key.                                                                  |
| 5xx                                    | Unexpected service/database failure                                                                                                                                                                                                  | Generic service error, preserve draft and intended key while Actor unchanged; inspect reads/explicit retry according to command contract. | Network / ambiguous command completion | May have committed even if no response arrived                                                                                                                                                                                       | Disable automatic mutation retries. For supported Price/Inventory/Observation identity reuse, explicit same-intent retry keeps exact payload/key. 409 messages are **not reliably machine-classifiable**. `ValidationRules.conflict` combines resource/identity conflict; ORM uses another generic changed message; DB integrity shares one generic detail. `type` encodes HTTP status, not a domain conflict code. The frontend cannot safely distinguish all stale/identity/unique/FK/provider/idempotency causes from current ProblemDetail, and must not invent `STALE_VERSION`, `ALREADY_BOUND` or similar transport codes. Known local validation/context can help explain choices without claiming the server returned a specific cause.

## 18. Query invalidation / read-after-write plan

Proposed protected query prefix is `['curation', opaqueSessionScope, ...]`; reuse existing session-scoped canonical keys for identical public projections, never mix admin Source/evidence responses into buyer keys. Every asynchronous mutation success/error handler must verify it still belongs to the initiating session before applying cache data, navigation or retry state. Cancellation cannot undo a committed server write; a late old-Actor completion cannot repopulate the new Actor's UI.
