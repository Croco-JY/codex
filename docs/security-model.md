# Security Model

Production uses Spring Security OIDC resource-server validation with issuer and audience. No passwords are stored. Local identity headers exist exclusively in the local profile, bound to loopback; never deploy this profile. Tenant access is checked centrally against membership on every protected request. Private storage has no public URLs. Production CORS is explicit, tokens are never logged, errors carry request IDs, and audit records reject updates/deletes. CSP and delivery headers are documented in infra. Production secrets belong in Secrets Manager.

[Phase 3F](phase-3f-secure-pattern-releases.md) adds a separately authenticated exact-release path with source-bound single-use recipient consent, permanent withdrawal/revocation, five-parent ACTIVE/version fencing and coherent final authorization. Private physical reads remain File-owned, bounded to the existing 10 MiB ceiling with anchored no-follow opening and exact size/SHA-256. Initial SQL completes before I/O; final SQL completes before bytes. The physical-transaction fence, fixed providers and sticky denial preserve the F01 security boundary. This does not weaken source membership checks, introduce an unchecked getter, impersonate a source Actor, or expose storage paths/digests in recipient DTOs. Private release JSON/binary is no-store; no new permanent per-download audit is added. See the implementation document for the service-owned filesystem and trusted-deployment limits; no universal hostile-host/JVM sandbox is claimed.
